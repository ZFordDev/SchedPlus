# ⭐ Start Here

SchedPlus is meant to be followed from the beginning.

Don’t jump to the latest version.

Start at the first commit, read the code, then move forward one step at a time.

Each version adds one idea. Nothing more.

That’s how you actually learn how software evolves.

---

# 📘 **1. How to Learn From SchedPlus**
SchedPlus is designed so you can **start at the very beginning** and watch the project grow step‑by‑step.

Each version introduces a new concept:

- v0.1 → basic Tkinter UI  
- v0.2 → saving & loading  
- v0.3 → logic separation  
- v0.4 → preparing for PyQt  
- v0.5 → PyQt UI  
- v0.6 → UI switching  
- v0.7 → Snap packaging  
- v0.8 → .deb packaging  
- v0.9 → Windows packaging  
- v1.0 → full release  

You can follow this evolution directly through GitHub’s version history.

---

# 📘 **2. How to View the Version History**
To learn SchedPlus properly, start at the earliest commit and move forward.

### **Version history link:**  
[https://github.com/zforddev/schedplus/commits/main](https://github.com/zforddev/schedplus/commits/main)

### Recommended approach:
1. Scroll to the **very first commit**  
2. Open it  
3. Read the code  
4. Read the commit message  
5. Move to the next commit  
6. Repeat  

This lets you see:

- how the project started  
- how features were added  
- how refactors were done  
- how packaging was introduced  
- how the architecture evolved  

This is the closest thing to “pair programming with the developer.”

# 📘 **3. How to Fork SchedPlus Correctly**
If you want to experiment or follow along:

### **Step 1 — Fork the repo**
Click **Fork** on GitHub.

### **Step 2 — Clone your fork**
```
git clone https://github.com/<yourname>/schedplus.git
```

### **Step 3 — Create a branch for learning**
```
git checkout -b learning
```

### **Step 4 — Optionally reset to an early version**
If you want to start at v0.1:

```
git checkout <commit-hash>
```

(You can find the hash in the commit history.)

### **Step 5 — Build forward at your own pace**
You can recreate each version yourself to reinforce learning.

# 📘 **6. Tips for Learning Effectively**
- Don’t rush — read each commit carefully  
- Try rewriting parts of the code yourself  
- Compare Tkinter and PyQt versions  
- Experiment with your own features  
- Follow the packaging guides step‑by‑step  
- Treat SchedPlus like a real project, not a tutorial  

SchedPlus is designed to teach **real software evolution**, not just syntax.

# Intentional Imperfections

SchedPlus is a learning project.
Some small UI quirks or minor inefficiencies are left intentionally to create opportunities for:

- issue reports
- community contributions
- debugging practice
- refactoring exercises

These imperfections never break the app — they exist to help you learn and participate.
